# Как работать над проектом

## Окружение

Для удобства работы над проектом используются инструменты из **Node.js** и **npm**. Все необходимые настройки произведены. Убедитесь, что на рабочем компьютере установлен актуальный LTS-релиз Node.js. Актуальная версия **Node.js** указана в файле `package.json` в поле `engines.node`. Затем, в терминале, перейдите в директорию с проектом и _единожды_ запустите команду:

```bash
npm install
```

Команда запустит процесс установки зависимостей проекта из **npm**.

## Запуск проекта

Перед первым запуском убедитесь, что установлены:

- актуальный LTS-релиз Node.js (см. `package.json`, поле `engines.node`);
- Docker (для запуска MongoDB через `docker-compose`).

### Шаги

1. Установите зависимости:

   ```bash
   npm install
   ```

2. Скопируйте `.env.example` в `.env` и при необходимости отредактируйте значения:

   ```bash
   cp .env.example .env
   ```

   В `.env` должны быть заполнены все переменные, перечисленные в разделе «Переменные окружения» ниже. Значения по умолчанию подходят для локального запуска с `docker-compose.yml` из корня проекта.

3. Поднимите MongoDB (и Mongo Express):

   ```bash
   npm run docker:up
   ```

   После этого MongoDB будет доступна на `localhost:${DB_PORT}` (по умолчанию `27017`), а веб-интерфейс Mongo Express — на [http://localhost:8081](http://localhost:8081).

4. Запустите REST API в режиме разработки:

   ```bash
   npm run dev:api
   ```

   Сервер будет доступен на `http://localhost:${PORT}` (по умолчанию `3000`).

5. Сборка и запуск в production-режиме:

   ```bash
   npm run start:rest
   ```

   Команда поднимет контейнеры, соберёт проект в `dist/` и запустит `dist/main.rest.js`.

6. Для работы с CLI:

   ```bash
   npm run cli -- --help
   ```

## Переменные окружения

Все настройки передаются через переменные окружения. Для удобства используется файл `.env` в корне проекта (не должен попадать в систему контроля версий). Пример со значениями по умолчанию — в `.env.example`.

| Переменная | Описание | Значение по умолчанию |
| --- | --- | --- |
| `PORT` | Порт REST-сервера | `3000` |
| `LOG_LEVEL` | Уровень логирования (`fatal`, `error`, `warn`, `info`, `debug`, `trace`, `silent`) | `info` |
| `LOG_FILE_PATH` | Путь к файлу лога | `./logs/cli-app.log` |
| `MOCK_DATA_URL` | URL источника тестовых данных для CLI (`--generate`) | `https://example.com/images` |
| `DEFAULT_DATA_PATH` | Директория по умолчанию для данных CLI | `./data` |
| `MONGO_URI` | Строка подключения к MongoDB | `mongodb://admin:admin@localhost:27017/six-cities?authSource=admin` |
| `MONGO_DB_NAME` | Имя базы данных | `six-cities` |
| `JWT_SECRET` | Секрет для подписи JWT | `change_me` |
| `JWT_EXPIRES_IN` | Время жизни JWT | `1d` |
| `UPLOAD_DIRECTORY` | Директория для загруженных файлов (аватары) | `./upload` |
| `DB_USER` | Пользователь MongoDB (используется `docker-compose`) | `admin` |
| `DB_PASSWORD` | Пароль MongoDB (используется `docker-compose`) | `admin` |
| `DB_PORT` | Порт MongoDB (используется `docker-compose`) | `27017` |
| `UI_USER` | Пользователь Mongo Express | `admin` |
| `UI_PASSWORD` | Пароль Mongo Express | `admin` |

При старте сервис проверяет наличие обязательных переменных. Если какая-то переменная не задана или не проходит валидацию схемы convict, сервис выводит сообщение об ошибке и завершает работу.

## Сценарии

В `package.json` предопределено несколько сценариев.

### Работа с Docker

- `npm run docker:up` — поднять контейнеры MongoDB и Mongo Express в фоне.
- `npm run docker:down` — остановить и удалить контейнеры (данные в томе сохраняются).
- `npm run docker:reset` — остановить контейнеры, удалить том и поднять заново (база будет пустой).

### Разработка

- `npm run dev:api` — запустить REST API в режиме разработки с автоперезагрузкой (`tsx watch`).
- `npm run dev:cli` — выполнить CLI-команду без предварительной компиляции.
- `npm run dev:full` — параллельно запустить REST API и mock-сервер (`json-server` на порту `4000`).
- `npm run dev` — поднять контейнеры и запустить REST API в режиме разработки.
- `npm run mock` — запустить mock-сервер с данными из `mocks/mock-server-data.json` на порту `4000`.

### Сборка и запуск

- `npm run compile` — скомпилировать TypeScript в директорию `dist`.
- `npm run build` — удалить `dist` и скомпилировать проект заново.
- `npm run clean` — удалить директорию `dist`.
- `npm run start:rest` — собрать проект и запустить REST API.
- `npm run start:cli` — запустить CLI из скомпилированного кода.

### CLI

- `npm run cli -- --version` — вывести версию приложения.
- `npm run cli -- --help` — вывести справку по командам.
- `npm run cli -- --import <path>` — импортировать данные из TSV-файла.
- `npm run cli -- --generate <n> <path> <url>` — сгенерировать TSV-файл с `n` тестовыми предложениями.

### Линтер

- `npm run lint` — проверить проект статическим анализатором **ESLint**.
- `npm run lint:fix` — то же с автоисправлением.

Линтер проверяет файлы только внутри директории `src`. При запуске ошибки выводятся в терминал.

### Запустить ts-модуль без компиляции

```bash
npm run ts -- <Путь к модулю с ts-кодом>
```

Пакет `ts-node` позволяет выполнить TS-код в Node.js без предварительной компиляции. Используется только на этапе разработки.

## Структура проекта

### Директория `src`

Исходный код проекта: компоненты, модули и так далее. Структура директории `src` может быть произвольной.

### Директория `specification`

Спецификация REST API в формате OpenAPI (YAML).

### Файл `Readme.md`

Инструкции по работе с учебным репозиторием.

### Файл `Contributing.md`

Советы и инструкции по внесению изменений в учебный репозиторий.

### Остальное

Все остальные файлы в проекте являются служебными. Пожалуйста, не удаляйте и не изменяйте их самовольно. Только если того требует задание или наставник.
